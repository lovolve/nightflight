# `board/` — 화면 네 개

🔴 **왜 이 글이 있나** (2026-10-25 — 이 제품은 플러그인이라 열어 보면
코드를 다 볼 수 있잖아 그래서 코드 품질이 중요해 / 기능만 잘 돌아가는 게 아니라 코드
품질도 안정적이어야 평판을 관리할 수 있어」):
이 폴더에는 **사람이 쓰는 파일과 도구가 짓는 파일이 섞여 있다.** 파일 이름만 보고는
가를 수 없어서, 처음 여는 사람이 **지어지는 파일을 손으로 고칠 수 있다.**
고치면 다음에 다시 지을 때 지워지고, 그 사이에는 화면이 틀린 답을 보인다.

## 어느 것이 무엇인가

| 파일 | 누가 쓰나 | 짓는 법 |
|---|---|---|
| `cockpit.html` | **사람** | — (손으로 고친다) |
| `관문셈.html` | **사람** | — (손으로 고친다) |
| `관문셈.json` | **도구** | `python3 tools/gen_gates_web.py` |
| `관문셈-조각.html` | **도구** | `python3 tools/gen_gates_embed.py` |

⛔ 아래 둘은 **손으로 고치지 않는다.** 두 파일 모두 맨 앞(또는 머리 주석)에 그렇게 적혀
있고, 낡으면 `tools/lint_gates_web.py` 가 **지문을 견주어** 울린다(턴 끝마다 돈다).

## 지어지는 둘은 왜 그렇게 큰가

`관문셈.json` 은 **미리 계산해 둔 표**다(경우 648가지).

⭐⭐ 까닭은 **규칙을 두 벌 두지 않기 위해서**다. 판정 규칙을 웹에 보내면 규칙이
`tools/gates.py` 와 화면 두 곳에 있게 되고, **한 곳이 반드시 낡는다**(이 저장소가 2026-09-30
에 그 값을 치렀다). 그래서 네 축이 가질 수 있는 답을 **전부 돌려 미리 계산**하고,
화면은 **표를 찾아보기만** 한다 → 규칙은 `tools/gates.py` **한 곳**에만 있다.

⛔ **그래도 검사가 필요하다** — 표는 낡는다(`data/관문.tsv` 나 `tools/gates.py` 가 바뀌면).
그것이 `tools/lint_gates_web.py` 가 하는 일이다: 다시 만들어 보고 **지문을 견준다.**

## 적는 꼴 — 머리말은 펼치고, 몸통은 한 줄

`관문셈.json` 은 **머리말을 펼쳐 적고 몸통(`표` 648칸)을 한 줄로** 적는다.

🔴 2026-10-25 에 세 꼴을 다 만들어 재서 정했다. **눌러서 보내는 크기는 4,707 · 4,570 ·
4,633바이트** — 137바이트 차이라 **크기는 고를 근거가 못 된다.** 그래서 읽는 사람 기준으로
정했다:

- 머리말을 펼치면 `head` 만으로 **무엇이고 어떻게 다시 짓나**를 안다.
- 몸통을 한 줄로 적으면 **기계 자료임이 한눈에 보인다** — 고치려 들지 않는다.
  줄 수가 **8,726 → 129** 로 줄어, 저장소를 훑는 사람의 눈에서 사라진다.

⛔ 더 줄이지 않는다. 열쇠를 번호로 바꾸면 1.8KB 를 아끼지만 **웹이 같은 번호를 만들어야**
하고, 그것은 **부호 규칙을 한 벌 더** 두는 것이다. 1.8KB 를 아끼려고 「두 곳에 두면 한 곳이
낡는다」를 사지 않는다.
