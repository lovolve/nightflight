  사용:
    ledger.sh 등록                                  # 이 폴더를 야간비행 프로젝트로 등록한다(사용자가 등록해 달라고 할 때만)
    ledger.sh 바로잡기 <종류> "<글 일부>" "<까닭>"      # 잘못 적은 줄을 옮긴다(화면 설계서 줄은 «화면:요소» 꼴 · «겹침» 은 겹친 줄 모두)
    ledger.sh 레드팀 <돌림|넘김> <때> ["<찾은 것>"]      # 권한 레드팀에 사용자가 한 답(때: 개발 · 출시 · 결제 · 로그인 · 개인정보 · 서버권한)
    ledger.sh 막음  "<무슨 일이 일어나던 중이었나>"  "<근거: 무슨 검사>"  "<안 막았으면 어떻게 될 뻔했나>"
      --항목 "<무엇에 대한 것>" --값 "<막은 것>"     # 조종석 «최근 기록» 칸 — 없으면 거절한다
    ledger.sh show  [단계이름]                      # 사용자에게 보이는 화면
    ledger.sh 결정  "<무엇을>" "<근거·인용>" "<전제>" "<주제 한 단어|빈칸>" "<묶임: 돈|시간|법|못되돌림|없음 … 한 줄>" \
      --항목 "<무엇에 대한 것>" --값 "<정한 것>" --조건 "<이것이 바뀌면>"   # 셋 다 없으면 거절한다
    ledger.sh 결정목록                              # 지금까지의 결정과 «그 전제»
    ledger.sh 되돌림 "<결정 일부 글자>"              # 되돌릴 때 그 위에 쌓인 것을 보인다
    ledger.sh 단계  "<이름>"                         # 단계를 넘는다 → «전제 점검»이 자동으로 뜬다
    ledger.sh 전제점검                               # 「이 전제들 아직 맞나요?」
    ledger.sh 전제바뀜 "<결정 일부>" "<무엇이 바뀌었나>" "<다시 볼 것|없음>"  # 남은것이 «자동으로» 생긴다
    ledger.sh 전제해소 "<결정 일부>" "<어떻게 해소됐나>"   # 깨졌던 전제가 다시 섰다
    ledger.sh 틀린전제                               # 되돌린 것들과 «그때 틀렸던 전제»를 모아 본다
    ledger.sh 사전예방 "<다음 단계에서 하실 일>" "<지금 신청해 두면 좋은 것|없음>"
    ledger.sh 기다림   "<무엇을 신청했나>" "<보통 걸리는 기간>" "<최대 며칠·숫자>"
    ledger.sh 기다림끝 "<무엇이 왔나>"                     # 와서 더 안 기다릴 때
    ledger.sh 문의권함 "<어느 기다림>" "<초안 둔 자리>" "<제가 넣어 둔 것>"
  앱에서 보는 조종석 (상태줄은 터미널 것이다 — 데스크톱 앱에서는 아티팩트가 그 자리다)
    ledger.sh 조종석 "<아티팩트 주소>"                   # 한 번만 등록한다
    ledger.sh 조종석반영                                 # 갱신했다고 표시 → 낡음 알림이 멈춘다
    ledger.sh 조종석준비                                 # 조종석에 보낼 JSON 을 만든다(쓰기는 모델이)
    ledger.sh 조종석동의 <네|아니오>                     # 첫 업로드 전 사용자 답을 적는다
    ledger.sh 조종석지금                                 # 큰 단계가 끝났을 때 턴 끝을 기다리지 않고 지금 올린다
  앱 온보딩 B-1~B-5
    ledger.sh 앱설정묻기                                 # B-1~B-4 묻는 말을 만든다
    ledger.sh 앱설정 <축> <값> [누가]                    # 축: 플랫폼·계정종류·계정만든날·돈받기·붙일서비스·기능·만들것
    ledger.sh 앱설정보기                                 # 지금 설정
    ledger.sh 관문                                       # B-5 — 「여섯은 안 걸립니다」를 «계산»한다
    ledger.sh 이어받기                                   # 지난 앱에서 들은 것을 보여주고 바뀐 것만 묻는다
    ledger.sh 사람확인                                   # 「그대로입니다」를 들었다고 적는다
  온보딩 「아는 낱말 체크」 — **한 번만**
    ledger.sh 낱말묻기                                   # 물어볼 말을 만든다(묻는 것은 모델이 대화에서)
    ledger.sh 아는낱말 "API" "커밋" ...                  # 답을 받는다. ⛔ 인자 0개 = 하나도 모름(그것도 답이다)
    ledger.sh 풀어쓸말                                   # 모델이 본다 — 「한 번 풀고 쓸 말」 목록
    (ledger.sh 낱말올림 — 훅이 부른다. 사람이 적지 않는다)
    ledger.sh 호칭 "<불러 달라는 말>"                    # 사용자가 정하면 적는다 · 빈 값이면 부르지 않기로
    ledger.sh 단계연결 "<프로젝트 단계명>" <0~8>     # 그 이름을 9단계 중 하나에 «사용자가» 연결한다
    ledger.sh 남은것 "<한 줄>" ["<설명키>"] ["<주제>"]  # 이 단계에서 아직 안 한 것
    ledger.sh 한국절차                               # 출시 전에 숨은 일 둘을 「남은 것」에 넣는다(이름은 옛 이름 — 나라별 법은 뺐다)
    ledger.sh 됐다 "<무엇이 됐나>" "<무엇이 확인했나 — 안 했으면 «안 함»이라고>" ["<주제>"] --세부 "<기능 › 세부기능>" [--세부 …]
    ledger.sh 못함 "<무슨 검사>" "<무엇이 없어서>" "<하실 일>"
    ledger.sh 풀림 "<검사 일부 글자>"                 # 이제 돈다
    ledger.sh 없어짐 "<일부 글자>" "<왜 더 이상 필요 없나>"  # 방향이 바뀌어 «안 하기로» 했다
    ledger.sh 못함목록
    ledger.sh 끝냄  "<일부 글자>"                    # 그것을 끝냈다
    ledger.sh 묶임                          # 고르신 기능에서 걸리는 것
    ledger.sh 묶임 "<정하려는 것>"          # 그 결정에서 걸리는 것
    ledger.sh 기능연결 "<주제>" "<기능 이름>"      # ⛔ 도구가 추측하지 않는다 — 사용자가 연결한다
    ledger.sh 기능진척                             # 기능마다 된 것/남은 것 · 놓치면 안 되는 것
    ledger.sh 기여동의                               # 여쭐 말을 만든다(묻는 것은 모델이 대화에서)
    ledger.sh 기여동의 "<사용자 말 그대로>"        # 들었다고 적는다 — 인용이 없으면 동의가 아니다
    ledger.sh 기여후보                               # 기록에서 «못 막은 것»을 뽑아 보인다
    ledger.sh 기여 "<일부 글자>"                     # 그 줄을 보낼 것으로 표시한다
    ledger.sh 기여목록                               # 무엇이 나갈 것인지 본다
    ledger.sh 기여취소 "<건id>"                      # 지운다
  「앱 개발을 시작할 때는 **구체적인 내용이 없는 게 당연하고**, 만들다 보면
    ledger.sh 카드  "<지금 결정하실 것>" "<왜 여쭙나>" "<나중에 정하면>" "<이것만 정하시면>" "<제가 맡는 것>"
