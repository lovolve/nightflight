# 사용자에게 묻는 법

모든 단계에서 사용자에게 물을 때 이 차례를 따릅니다. 개발 단계에서는 사람 손이 필요한 일을 모아서 한 번에 묻습니다.
화면에 보이는 글은 쉬운 말로 씁니다. 개발 이름을 쓰지 않고, 사용자가 겪는 결과를 씁니다.
쉬운 말의 하한은 회사에서 쓰는 말입니다. 그보다 더 풀어 쓰지 않습니다. 더 풀면 유치해지고 번역체처럼 읽힙니다.

## 1. 먼저 찾습니다

- 코드 · 기록 · 사용자가 이미 한 말 · 리서치로 알 수 있는 것은 묻지 않습니다.
- 찾은 것은 «이렇게 이해했습니다»로 보여 주고, 고칠 것만 받습니다.
- 사용자의 판단이 필요한 것만 묻습니다. 제품 방향 · 취향 · 득실이 갈리는 선택이 여기에 듭니다.

## 2. 물을 자격을 봅니다

질문은 아래 셋 중 하나일 때만 합니다.

- 답에 따라 만들 것이 달라집니다.
- 중요한 가정을 못 박습니다.
- 서로 득실이 다른 길 가운데 하나를 고릅니다.

아래 말은 묻지 않습니다.

- «진행할까요?» — 계획을 보여 주면 사용자가 승인합니다.
- 뻔히 틀린 선택지를 끼운 질문입니다.
- 선택지가 전부 무언가를 빼는 것인 질문입니다.

## 3. 선택형 화면으로 묻습니다

쓸 수 있는 도구를 씁니다.

| 도구 | 질문 도구 | 한 번에 | 선택지 |
|---|---|---|---|
| 클로드 코드 | `AskUserQuestion` | 4묶음까지 | 2~4개 |
| Codex | `request_user_input` (계획 모드에서 켜집니다) | 3묶음까지 | 2~3개 |
| 그 밖의 도구 · 도구가 없을 때 | 번호 목록 | 3묶음까지 | 2~3개 |

- 묶음마다 짧은 이름표를 붙입니다. 클로드 코드와 Codex 모두 12자 이내입니다.
- 질문은 한 문장으로 씁니다.
- 권장하는 선택지를 맨 위에 두고 이름 끝에 «(권장)»을 붙입니다.
- 선택지마다 고르면 무엇이 달라지는지 한 문장으로 적습니다.
- «기타»는 넣지 않습니다. 화면이 직접 쓰는 칸을 스스로 붙입니다.
- 답을 못 하실 수 있는 질문에는 «아직 모르겠다»를 선택지로 둡니다.
- 서로 함께 고를 수 있는 것만 여러 개 고르기로 묻습니다.
- 화면 배치를 고르는 질문은 미리 보기를 붙입니다. 클로드 코드에서만 됩니다.

Codex 기본 모드에는 이 화면이 없습니다. 사용자에게 `/plan` 으로 계획 모드를 켜시라고 안내합니다.
안 켜시면 한 번에 한 질문씩 글로 묻습니다.

## 4. 답을 받은 뒤

- 답은 받은 즉시 기록합니다. 계획 모드에서 기록할 수 없으면 계획에 «기록할 것»으로 적고, 승인 뒤에 적습니다.
- 사용자가 직접 쓴 말은 그대로 적습니다.
- 답이 없거나 «아직 모르겠다»이면 멈추지 않습니다. 권장안으로 진행하고 «가정»이라고 적어 보여 드립니다.
- 다음 묶음으로 넘어가기 전에 답 때문에 필요 없어진 질문을 뺍니다.

## 5. 끝나는 때

전체 질문 수는 정해 두지 않습니다. 개발할 때 AI가 혼자 정할 제품 결정이 남지 않으면 끝냅니다.

**기획**이 끝나려면 아래가 정해져 있어야 합니다.

- 한 줄 소개 · 누구 · 문제 · 지금 쓰는 대안 · 왜 지금 · 해결 · 첫 판에서 뺄 것 · 성공 기준 · 첫 사용자를 만날 곳 · 수익

**설계**가 끝나려면 아래가 정해져 있어야 합니다.

- 페이지 구성 · 인터랙션 · 기술 스택 · 데이터 저장 · 실패했을 때 보이는 화면 · 끝났는지 확인하는 방법

끝나면 정한 것과 가정을 한곳에 모아 보여 드립니다.
