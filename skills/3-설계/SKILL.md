# 3-설계

> ⭐ **이 파일에는 «무엇을 하는 단계인가»만 있다.**
> 증상 표·실제 절차·판정 기준·사고 이력은 **두뇌가 내려준다**(기획 §43-6).
> ⛔ 그것을 여기 적지 않는다 — **본체는 서버에서 내려온다.**
> `tools/lint_skill_leak.py` 가 그것을 막는다.

## 무엇을 하는 단계인가

**결정 ③** 기능 확정 — 넣을 것 / 뺄 것 / 다음 버전.

⭐ **확정한 기능은 «설계표»로 남긴다** — 단계 → 기능 → 세부기능 자리를 이때 만든다
(설계 단계에서 만들 기능을 쭉 정하고, 끝내 가는 것을 표시한다.)

```bash
"${CLAUDE_PLUGIN_ROOT}/bin/ledger.sh" 기능추가 4 <기능>                 # 기본 세부기능이 있는 기능은 자리가 같이 깔린다
"${CLAUDE_PLUGIN_ROOT}/bin/ledger.sh" 기능추가 4 <기능> <세부기능> …     # 기본이 없거나 사용자 기획대로
"${CLAUDE_PLUGIN_ROOT}/bin/ledger.sh" 세부기능 4 <기능> <세부기능>       # 기획으로 하나 더
"${CLAUDE_PLUGIN_ROOT}/bin/ledger.sh" 설계표                            # 확인받을 목록
```

⛔ 만든 목록은 **사용자에게 확인받는다** — 무엇을 넣고 뺄지는 사용자 몫이다.
⛔ 조종석의 진행경과는 이 자리를 채워 가는 것이다 — 끝낸 일 기록으로 진행을 말하지 않는다.

## ⭐ 화면 흐름 — 조종석의 «화면 흐름»이 이것으로 그려진다

⭐ 흐름도는 정보는 좋지만 낯설다. **좋은 정보보다 바로 이해되는 것이 먼저다.**
→ 조종석은 «사용자가 하는 일»마다 한 줄을 보이고, 누른 줄 하나만 폰 화면 그림으로 편다. 화면을 누르면 그 아래에 화면설계서를 편다.

```bash
"${CLAUDE_PLUGIN_ROOT}/bin/ledger.sh" 화면 <짧은 이름> "<한 줄 설명>"
"${CLAUDE_PLUGIN_ROOT}/bin/ledger.sh" 화면이름 <화면> "<풀어 쓴 이름>"          # 줄인 이름이면 꼭
"${CLAUDE_PLUGIN_ROOT}/bin/ledger.sh" 화면언제 <화면> "<사용자가 언제 이 화면을 보나>"
"${CLAUDE_PLUGIN_ROOT}/bin/ledger.sh" 화면하는일 <화면> "<사용자가 여기서 하는 일>"
"${CLAUDE_PLUGIN_ROOT}/bin/ledger.sh" 화면요소 <화면> "<보이는 것>" <기능> [세부기능]
"${CLAUDE_PLUGIN_ROOT}/bin/ledger.sh" 화면이동 <화면> <다음 화면> "<무엇을 하면>"
"${CLAUDE_PLUGIN_ROOT}/bin/ledger.sh" 화면갈림 <화면> "<이 화면 뒤에 갈리는 물음>"   # 갈릴 때만 — 이동 조건은 «예» · «아니오 · …»
"${CLAUDE_PLUGIN_ROOT}/bin/ledger.sh" 화면상태 <화면> "<상태>" ["<다음으로 가는 때>"] [나쁨]   # 시간 · 결제 · 서버로 바뀌는 화면만
"${CLAUDE_PLUGIN_ROOT}/bin/ledger.sh" 화면종류 <화면> 폰|모니터|메일
"${CLAUDE_PLUGIN_ROOT}/bin/ledger.sh" 화면일 "<하는 일>" "<언제 — 비워도 됨>" <화면> ["<화면|화면>"] …   # «|» 는 «또는»
"${CLAUDE_PLUGIN_ROOT}/bin/ledger.sh" 화면빼기 <화면> "<왜 — 없앤 화면 등>"
"${CLAUDE_PLUGIN_ROOT}/bin/ledger.sh" 기능빼기 <기능> "<왜 — 없앤 기능 · 합친 기능 등>"
```

⭐ **없앤 화면 · 기능은 «빼기»로 적는다**(없앤 기능·화면은 설계와 개발, 그리고 이어진 모든 곳에서 같이 바뀌어야 한다).
  화면빼기는 그 화면으로 가던 이동 · 하는 일 차례에서도 빼고, 기능빼기는 모든 단계의 설계표 줄 · 그 기능을 가리키던 화면 요소 · 엮임 · 상태 그림에서도 뺀다.
  ⛔ 화면 요소의 설명을 지우거나 기록 줄을 손으로 지우지 않는다 — «없앴다»는 기록이 남아야 나중에 왜 빠졌는지 안다.

⭐ **하는 일**은 사용자 말로 쓴다 — «처음 시작하기» · «쓴 돈 적기» · «이번 달 돌아보기». 기능 이름이 아니다.
  클로드가 기획 · 화면의 «언제 보나» · 이동에서 만든다. ⛔ 이것 때문에 질문을 늘리지 않는다.
  모든 화면이 어느 하는 일엔가 들어야 한다 — 대화 끝 검사가 빠진 화면과 없는 화면을 알린다.

⭐ 화면이 바뀌면(새 화면 · 없어진 화면 · 이동이 바뀜) **개발 중에도** 같은 명령으로 고친다 —
  같은 두 화면의 이동을 다시 적으면 조건만 바뀐다.
⛔ 「언제 보나」 · 「하는 일」이 빠지면 대화 끝 검사(`lint_screen_spec`)가 알린다 — 조종석에는 «아직 적지 않았습니다»로 나간다.

## 두뇌에 무엇을 묻나

레퍼런스 갈래와 실측값은 **두뇌가 내려준다**.

⭐ **부르는 법** — 이 단계에 들어오면 **먼저 묻는다**:

```bash
"${CLAUDE_PLUGIN_ROOT}/bin/두뇌.sh" 3 <갈래>
```

갈래를 모르면 아무 말이나 넣으면 **물을 수 있는 갈래 목록**이 돌아온다.
⛔ 받은 것을 **파일로 적어 두지 않는다** — 적는 순간 노하우가 깔려 나간다(기획 §43-6).
⛔ 못 받아도 **멈추지 않는다.** 아는 것만으로 진행하고 **「두뇌에서 못 받았다」고 적는다.**

## ⭐⭐ 기능을 확정한 «뒤» — 기능끼리의 지도를 적는다

⭐ 「고칠 곳을 다 안다」는 **고쳐 달라고 할 때 분석해서 찾는다**는 뜻이 아니다.
**설계 때 지도를 만들어 두었다가, 고칠 때 그 지도를 보고 확인한다**는 뜻이다.
⛔ 그래서 설계에 부품 지도가 빠지면 안 된다 — 기능끼리 어떻게 이어지고
부딪치고 어느 차례로 도는지까지 거기 적는다.

🔴 **왜 이 자리가 생겼나 — 실측(2026-10-22).** 장치는 2026-10-10 에 다 만들어져 있었는데
   야간비행 자신의 지도 11줄 중 **10줄이 「깨졌다」**(고장난 뒤에 배운 것)이고
   설계 때 적기로 한 출처 **「리서치」는 0줄**이었다.
   ⛔ **설계 스킬에 적는 자리가 없어서** 아무도 안 적었다. 장치가 아니라 **단계가** 없었다.

```bash
# ① 기능끼리 — 「이걸 고치면 무엇도 봐야 하나」
"${CLAUDE_PLUGIN_ROOT}/bin/ledger.sh" 영향 <고치는쪽> <같이볼쪽> "<종류>: <무엇을>" 리서치
#   종류 셋: 같은것을쓴다(둘이 같은 것을 들고 있다) · 순서가있다(이것이 먼저) · 같은화면(한 화면에)
"${CLAUDE_PLUGIN_ROOT}/bin/ledger.sh" 영향목록

# ② 기능마다 — 「지금 어느 상태인지와 다음에 갈 수 있는 곳」
"${CLAUDE_PLUGIN_ROOT}/bin/ledger.sh" 상태 <기능> <상태> <갈수있는곳,쉼표> 대표님
#   더 갈 곳이 없으면 갈 곳에 «끝» 을 적는다 — 빈 칸은 「없다」가 아니라 「안 적었다」다
"${CLAUDE_PLUGIN_ROOT}/bin/ledger.sh" 상태목록
```

⭐ **①은 리서치가 주는 것만 받는다** —
  설계 때 **사용자에게 묻는 질문을 늘리지 않는다.** 비슷한 앱을 보며 보이는 딸림만 적는다.
⭐ **②는 사용자가 정하실 수 있다** — 「결제 실패하면 어디로 갑니까」는 제품 질문이다.
  ⛔ 제가 정했으면 출처를 **「내판단」**으로 적는다. 목록이 그 수를 따로 말한다.

⛔ **①②가 비어도 「딸린 것이 없다」고 말하지 않는다** — 「**지도에 안 적혀 있다**」다.
  0 을 안전으로 읽히게 두면 **지도가 없는 것보다 나쁘다**(사람이 믿고 안 본다).

## ⛔ 못 — 이 단계에서 하지 않는 것

1. **내 취향으로 바로 그리지 않는다** — 레퍼런스를 먼저 모은다
2. **「~같다」는 레퍼런스 언어다** — 다시 만들라는 뜻이 아니라 가져오라는 뜻이다
3. **첫 출시는 최소가 기본값**
4. 기술 설계를 보여주지 않고 **결과만** 말한다 — 「만들 수 있어요 / 어려워요 — 이유」
5. **사용자 말을 내 해석으로 번역해 완제품으로 만들지 않는다** — 갈래로 낸다
6. **기능 목록만 만들고 끝내지 않는다** — 점만 적고 **선을 안 적으면** 「하나 고치면 다른
   게 망가진다」가 그대로 남는다(어느 채팅 제품에서 **100번 가까이** 겪은 자리다)
