# 4-개발

> ⭐ **이 파일에는 «무엇을 하는 단계인가»만 있다.**
> 증상 표·원인·막는 순서는 **두뇌가 내려준다**(기획 §43-6 이 이 파일을 직접 지목했다).
> ⛔ 그것을 여기 적지 않는다. `tools/lint_skill_leak.py` 가 막는다.

## 무엇을 하는 단계인가

가장 긴 구간이고 **말을 걸지 않는다.** 사람 손이 필요한 일은 **모아서 한 번에** 묻는다.

⭐ **설계표의 자리를 채워 간다** — 세부기능 하나를 끝낼 때마다 그 자리의 상태를 바꾼다:

```bash
"${CLAUDE_PLUGIN_ROOT}/bin/ledger.sh" 세부상태 <기능> <세부기능> 완료 "<무엇으로 확인했나>"
"${CLAUDE_PLUGIN_ROOT}/bin/ledger.sh" 세부상태 <기능> <세부기능> "확인 필요" "<짧은 이름표>"
"${CLAUDE_PLUGIN_ROOT}/bin/ledger.sh" 세부상태 <기능> <세부기능> "방법 찾는 중" "<짧은 이름표>"
```

상태는 다섯뿐이다 — 시작 전 · 진행 중 · 완료 · 확인 필요 · 방법 찾는 중.
⛔ **「완료」에는 무엇으로 확인했는지를 붙인다**(예: 「휴대폰에서 눌러 봄」). 없거나 「안 함」이면 «확인 필요 · 확인 안 함»으로 적힌다.
⛔ 설계표에 없는 세부기능은 «완료»로 못 적는다 — 새로 생기면 사용자에게 확인받고 자리부터 만든다.
⛔ **끝낸 일을 기록할 때(`ledger.sh 됐다`)는 어느 세부기능의 일인지를 붙인다** — `--세부 "<기능> › <세부기능>"`(여럿이면 여러 번, 세부기능의 일이 아니면 `--세부 없음`). 그 기록이 «확인 안 함»이면 그 세부기능은 조종석에 «확인 필요»로 보인다.

## 이 단계의 고유한 고장 — 한 줄로

**「만들었다」와 「이어졌다」는 다르다.** 각 조각은 멀쩡하고 **«사이»가 빈다.**
⭐ 증상 표와 막는 순서는 두뇌가 내려준다.

## 두뇌에 무엇을 묻나

증상별 처방 · 모듈 카탈로그 · 「이 기능은 세 번째입니다」.

⭐ **부르는 법** — 이 단계에 들어오면 **먼저 묻는다**:

```bash
"${CLAUDE_PLUGIN_ROOT}/bin/두뇌.sh" 4 <갈래>
```

갈래를 모르면 아무 말이나 넣으면 **물을 수 있는 갈래 목록**이 돌아온다.
⛔ 받은 것을 **파일로 적어 두지 않는다** — 적는 순간 노하우가 깔려 나간다(기획 §43-6).
⛔ 못 받아도 **멈추지 않는다.** 아는 것만으로 진행하고 **「두뇌에서 못 받았다」고 적는다.**

## ⛔ 못 — 이 단계에서 하지 않는 것

1. **말을 걸지 않는다.** 묻는 자리는 미리 설계된 결정 지점뿐이다
2. **「빼거나 바꿀까요?」를 묻지 않는다**(2026-09-25 폐기) — 선택지 둘이 다 축소다
3. **같은 길을 세 번 가고 「안 된다」고 하지 않는다**
4. **값이 두 곳에 있으면 검사가 아니라 «구조»로 푼다** — 한 곳이면 볼 필요가 없다
5. **디스크를 개발 중에도 본다** — 쌓이면서 막힌다
