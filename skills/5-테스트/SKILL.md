# 5-테스트


## 무엇을 하는 단계인가

**결정 ④** 화면 확인.

⭐ **AI가 할 수 있는 확인은 AI가 먼저 한다.** 테스트 칸은 두 묶음으로 깔린다.
- «AI가 하는 확인»: 처음 켜서 끝까지 한 바퀴 · 자동 시험 통과 · 작동 안 하는 버튼과 못 가는 화면 없음 · 실패 상황에서 보이는 화면 · 다른 화면 크기
- «직접 하실 확인»: 진짜 휴대폰 · 실제 계정 로그인과 실거래 결제 · 써 보고 어색한 곳 — 조종석 «직접 테스트할 일»에 바로 보인다
⛔ AI 몫을 사용자에게 넘기지 않는다. 해 보고 막혔을 때만 `ledger.sh 세부상태 <기능> <세부> "확인 필요" "직접 — <막힌 까닭>"` 으로 넘긴다.
⭐ 단계를 끝내는 조건은 «AI가 지금 할 수 있는 일이 남지 않은 때»다 — 직접 하실 확인 · 바깥 답 기다림(`ledger.sh 세부언제`)은 붙잡지 않고 다음 단계로 따라간다.

## 두뇌에 무엇을 묻나

무엇을 전화기로 봐야 하는지의 목록은 **두뇌가 내려준다**.

⭐ **부르는 법** — 이 단계에 들어오면 **먼저 묻는다**:

```bash
"${CLAUDE_PLUGIN_ROOT}/bin/brain.sh" 5 <갈래>
```

갈래를 모르면 아무 말이나 넣으면 **물을 수 있는 갈래 목록**이 돌아온다.
⛔ 받은 것을 **파일로 적어 두지 않는다** — 적는 순간 노하우가 깔려 나간다.
⛔ 못 받아도 **멈추지 않는다.** 아는 것만으로 진행하고 **「두뇌에서 못 받았다」고 적는다.**

## ⛔ 못 — 이 단계에서 하지 않는 것

1. **스크린샷은 지시받았을 때만** 찍는다 — 한 장에 1~2분이고 그동안 기다리신다
2. **안 찍고 되는 검증은 다 하고**, 눈으로 못 본 것은 **「눈으로 확인 안 함」**이라고 적는다
3. **시뮬레이터는 두 번 실패하면 멈춘다** — 무엇을 하려 했고 어떤 오류였는지 보고한다
4. `${CLAUDE_PLUGIN_ROOT}/tools/shot.sh` 를 쓴다 — 직접 조합하지 않는다. 안드로이드 앱이면 스스로 에뮬레이터 쪽(`tools/shot_android.sh`)으로 넘긴다. iPhone 과 안드로이드를 둘 다 내는 앱에서 안드로이드를 찍으려면 `SHOT_PLATFORM=android` 를 붙인다
