# 레드팀

> 🔴 2026-10-28 — **설계 안정성과 보안만큼은 허술하지 않게 채운다** ·
> 레드팀은 **권하기만** 한다 — 왜 필요한지 설명하고, 사용자는 안 돌리고 넘어갈 수 있다.

## 언제

`ledger.sh` 가 «레드팀 권함»을 찍었고, 사용자에게 까닭을 말씀드린 뒤 **사용자가 돌리자고 했을 때만** 돌린다.
건너뛰자고 하시면 `ledger.sh 레드팀 넘김 <때>` 로 적고 하던 일을 이어 간다 — 다시 권하지 않는다.

## 어떻게

두 팀을 **따로, 같이** 띄운다(서로의 답을 보지 않게). 팀마다 이 프로젝트의 기록(정한 것 · 기능 표 · 화면 설계서)과 코드를 읽힌다.

1. **개발팀** — 이대로 만들면 어디서 무너지나
   - 기능 표에 있는데 코드에 없는 것 · 정한 것과 반대로 만든 것(예: «서버 없음»으로 정했는데 서버에 저장)
   - 기능 사이 연결이 빠진 곳 · 데이터 구조를 나중에 바꾸면 기존 사용자 기록이 깨지는 곳
   - 실패했을 때(네트워크 끊김 · 결제 취소 · 앱 종료) 사용자가 보는 화면이 비거나 데이터가 반만 남는 곳
2. **보안팀** — 남이 이걸 어떻게 악용하나
   - 로그인: 남의 계정으로 들어가는 길 · 비밀번호 · 토큰을 어디에 두나
   - 비밀값: 코드 · 저장소 · 앱 안에 박힌 키(서버 비밀 키가 앱에 들어 있으면 가장 급하다)
   - 권한: 서버 · 데이터베이스가 «로그인한 본인 것만» 읽고 쓰게 막혀 있나
   - 개인정보: 무엇을 모으나 · 어디로 보내나 · 지울 수 있나
   - 결제: 돈을 안 내고 쓰는 길 · 두 번 결제 · 환불 뒤에도 계속 쓰는 길

팀마다 찾은 것을 **«무엇이 · 어디서 · 그러면 사용자에게 무슨 일이»** 꼴로 내게 하고, 급한 순서로 줄 세운다.
⛔ 고칠지 말지는 사용자가 정한다. 찾은 것을 «이미 고쳤다»고 넘겨짚지 않는다.

## 적기

다 돌리면 사용자에게 급한 것부터 쉬운 말로 말씀드리고 적는다:

```bash
"${CLAUDE_PLUGIN_ROOT}/bin/ledger.sh" 레드팀 돌림 <때> "<찾은 것 한 줄 — 없었으면 «찾은 것 없음»>"
```

때: 개발 · 출시 · 결제 · 로그인 · 개인정보 · 서버권한.

## ⛔ 못

1. 사용자가 돌리자고 하지 않았는데 돌리지 않는다. 건너뛰어도 막지 않는다.
2. 레드팀이 찾은 것을 사용자에게 안 보이고 고치지 않는다 — 먼저 말씀드린다.
