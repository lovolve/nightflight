# 2-검증

> ⭐ **이 파일에는 «무엇을 하는 단계인가»만 있다.**
> 증상 표·실제 절차·판정 기준·사고 이력은 **두뇌가 내려준다**(기획 §43-6).
> ⛔ 그것을 여기 적지 않는다 — **본체는 서버에서 내려온다.**
> `tools/lint_skill_leak.py` 가 그것을 막는다.

## 무엇을 하는 단계인가

**결정 ②** 진행 / 수정 / 접기 — 사용자가 낸다.

## 두뇌에 무엇을 묻나

레드팀 브리프와 규정 대조 기준은 **두뇌가 내려준다**.

⭐ **부르는 법** — 이 단계에 들어오면 **먼저 묻는다**:

```bash
"${CLAUDE_PLUGIN_ROOT}/bin/두뇌.sh" 2 <갈래>
```

갈래를 모르면 아무 말이나 넣으면 **물을 수 있는 갈래 목록**이 돌아온다.
⛔ 받은 것을 **파일로 적어 두지 않는다** — 적는 순간 노하우가 깔려 나간다(기획 §43-6).
⛔ 못 받아도 **멈추지 않는다.** 아는 것만으로 진행하고 **「두뇌에서 못 받았다」고 적는다.**

## ⛔ 못 — 이 단계에서 하지 않는 것

1. **판정하지 않는다** — 재료를 주고 결론은 사용자가 낸다(2026-09-25 폐기 지시)
2. **그래도 맞장구는 막는다** — 나쁜 것을 좋게 말하지 않는다
3. **규정만 읽고 우려를 말하지 않는다** — 같은 «행위»를 하는 앱을 먼저 본다
4. **못 봤으면 「확인 못 했다」고 밝히고** 말한다

## 확인한 것을 적는 꼴

검증 표의 항목 하나를 확인하면 이렇게 적는다 — 조종석이 결론을 위 상자로, 근거를 «이름 · 값» 짝으로 그린다.

```bash
"${CLAUDE_PLUGIN_ROOT}/bin/ledger.sh" 세부상태 "<묶음>" "<항목>" 완료 "<결론> — <근거 이름>: <값> · <근거 이름>: <값> (출처)"
```

- 결론은 **찾은 사실**이다(예: «1위 앱 불만 1위는 광고다»). 진행·접기 같은 판정은 적지 않는다 — 위 «못» 1.
- « — »가 없으면 조종석은 결론 상자 없이 근거만 보인다.
